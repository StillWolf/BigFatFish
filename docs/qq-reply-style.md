# QQ 分条聊天与表情包

## 行为

小肥鱼根据语气决定一条说完，或自然分成两三个短文字气泡。仅在模型独占一行写出 `[next]` 时拆分；普通换行、段落和围栏代码中的同名文字保持原样。单次输出超过三个片段时，后续内容合并进第三条，保留原文。

同一聊天按队列发送，文字气泡间随机停顿约0.65—1.3秒。不同聊天的队列独立。

情绪合适时，模型可在回复末尾独占一行写 `[sticker:准确收藏名]`。桥从已有收藏中取图，等整轮文字发送完成后，再停顿约0.9—1.5秒，单独发送一张图。未知名称只跳过补图，不影响文字。

补图至少相隔90秒，并有两轮其他回复间隔；不连续发相同图片。图片由模型根据实际语气选，桥不随机配图。也可调用 `qq_face_send(name, after_reply:true)` 安排尾随表情；未开启该参数时，保留显式单独发送表情的用途。

## 模型输出格式

```text
哼
[next]
才没有想你
[sticker:鲸鱼娘得意]
```

用户收到两个文字气泡，随后可能收到一张图，收不到这些控制标记。不是每次聊天都拆，也不是每轮都带图。

## 发送与维护

- 分条和选表情沿用同一次模型生成，不为拆条或挑表情额外调用模型。会话提示带有少量具名库存，陌生图片仍需先认清再选。
- 每轮主动发言只判定一次出站额度，多气泡与尾随图沿用该轮结果。直接私聊、群内明确找她时继续免主动限流。
- 注入干跑不发送；文字被限流、发送失败或服务停止时，不再补图。服务停止会取消等待中的分条延时。
- 消息 ID 仍写入原有撤回记录；尾随图失败有追踪记录，不重发已成功的文字。
- 记忆和 TTS 使用去掉控制标记的正文；不会为分条生成额外的对话回合，也不允许编造对方台词。
- `qq-runtime.json` 的 `outbox.chatsPending` 表示还有待发送内容的聊天数；部署重载时应同时等待模型与发送队列空闲。

实现位于 `dsh-qq-onebot-bridge/lib/reply-text.js` 的展示格式解析，以及 `lib/bridge.js` 的会话发送队列。
